# AI 现场拍摄指导助手 · 目标函数一页纸定义

版本 v1.0 · 2026-11-22 · 负责人：Bridge

---

## 1. 问题定义

给定当前取景画面特征向量 x 与用户自然语言意图 I，求一组**可执行拍摄动作** A*，使调整后的画面尽可能符合意图。

```
A* = argmax  S( T(x, A), I )
     A ∈ P
```

- `x`：当前画面特征（见第 2 节）
- `I`：用户意图，映射为镜头类型 + 权重向量（见第 3 节）
- `P`：可执行动作集合（`phrases.json`，50 条）
- `T(x, A)`：动作 A 作用于画面 x 后的特征估计，由规则库 `rules.json` 近似
- `S`：机位质量评分函数（见第 4 节）

**为什么不用 3D 最优坐标**：真实拍摄现场没有场景结构信息，无法计算机位在三维空间中的最优位置。因此把"找机位"降维成**画面反馈式指导**——观察当前画面与目标的差距，输出用户能直接执行的动作。

---

## 2. 画面特征向量

```
x = ( r, c, l, g )
```

| 符号 | 含义 | 取值范围 | 获取方式 |
|---|---|---|---|
| r | 主体占画面比例 | [0, 1] | 端侧 MediaPipe 主体框面积 / 画面面积 |
| c | 背景复杂度 | [0, 1] | 背景区域边缘密度（Canny）归一化 |
| l | 光线方向类别 | {front, side, back, low, golden} | 云端多模态模型判断 |
| g | 视线空间 | [0, 1] | 主体朝向一侧的空白面积 / 画面面积 |

---

## 3. 意图到权重的映射

用户意图 I 经关键词匹配落到一个镜头类型 k（5 类），权重向量取自 `intent_weights.json`：

```
w(k) = ( w₁, w₂, w₃, w₄ ),   Σwᵢ = 1
```

| 镜头类型 k | w₁ 主体 | w₂ 背景 | w₃ 光线 | w₄ 视线 |
|---|---|---|---|---|
| 人像特写 portrait_closeup | 0.40 | 0.25 | 0.20 | 0.15 |
| 人物中景 portrait_medium | 0.30 | 0.20 | 0.20 | 0.30 |
| 风光环境 landscape | 0.15 | 0.40 | 0.35 | 0.10 |
| 产品静物 product | 0.35 | 0.35 | 0.25 | 0.05 |
| 情绪叙事 emotional | 0.20 | 0.20 | 0.35 | 0.25 |

每类同时给出各维度的目标区间 `[aᵢ, bᵢ]` 或目标集合 `Lᵢ`。

---

## 4. 四个评分函数

所有 fᵢ 归一化到 [0, 1]，越接近 1 越好。

### 4.1 主体占比分 f₁

目标区间 `[a, b]`，当前值 r：

```
f₁(r) = 1                                  若 a ≤ r ≤ b
      = max(0, 1 − (a − r) / a)             若 r < a
      = max(0, 1 − (r − b) / (1 − b))       若 r > b
```

### 4.2 背景干扰分 f₂

目标上限 u（越低越干净），当前值 c：

```
f₂(c) = 1                                  若 c ≤ u
      = max(0, 1 − (c − u) / (1 − u))       若 c > u
```

### 4.3 光线角度分 f₃

目标集合 L（如 {side, back}），当前类别 l：

```
f₃(l) = 1.0    若 l ∈ L
      = 0.4    若 l ∉ L        （保留部分分：光线可通过走位调整）
```

### 4.4 视线空间分 f₄

目标区间 `[a, b]`，当前值 g，形式同 f₁。

### 4.5 总评分

```
S(x, I) = w₁·f₁(r) + w₂·f₂(c) + w₃·f₃(l) + w₄·f₄(g)
```

**用途**：① 量化当前画面有多差；② 计算每个候选动作执行后的预期收益 ΔS。

---

## 5. 约束条件

```
焦段   f ∈ [1x, 5x]              （手机物理变焦范围）
机位高度 h ∈ [0.2m, 2.0m]        （蹲下到举过头顶）
物理可达性：原型阶段用画面反馈代替，不做 3D 碰撞检测
设备能力：光圈控制可选，无则排除依赖光圈的候选动作
```

---

## 6. 差距 → 动作映射

1. 对每个维度计算加权差距：
   ```
   dᵢ = wᵢ · ( fᵢ_target − fᵢ_current )
   ```
2. 取 |dᵢ| 最大的维度作为**主要矛盾**。
3. 在 `rules.json` 中筛选：`condition.field = 主要矛盾维度` 且 `applies_to` 包含当前镜头类型。
4. 按 `priority` 降序排列候选动作。
5. 对每个候选动作，估计执行后的特征变化，计算 `ΔS = S(x') − S(x)`。
6. 按 ΔS 降序取 Top-3，附上 `phrases.json` 中的 reason_template。

**输出**：不再是分数或坐标，而是"后退两步 / 换 3.2x / 机位降到腰部"+ 一句为什么。

---

## 7. 求解方法

| 阶段 | 方法 | 说明 |
|---|---|---|
| v1（原型） | 规则匹配 + ΔS 排序 | 动作组合长度 ≤ 2，枚举即可 |
| v2 | 网格搜索 | 对动作参数（步数、倍率）离散枚举 |
| v3 | 遗传算法 / 粒子群 | 动作序列组合优化，与国赛建模方法复用 |

---

## 8. 评估指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 一致率 | 引擎输出与"懂摄影的人"判断一致的比例 | ≥ 70%（20 张测试图） |
| 可执行率 | 话术无需二次解释即可执行的比例 | ≥ 90% |
| 端到端延迟 | 按按钮到首条建议出现 | < 5 秒 |
| 有效率 | 用户按建议调整后画面确实变好的比例 | ≥ 60%（5 人试用） |

---

## 9. 与大创 / 竞赛的复用点

- 多目标加权评分 + 约束优化：国赛常见题型
- 规则库与数据标注：可形成 90 条标注数据集
- 一致率评估：可作为模型有效性验证章节
- 三份 JSON + 一份 CSV：可直接作为大创项目的"数据与知识库"材料
